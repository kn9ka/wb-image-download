# wb-image-download

## Подход к получению медиа

Приложение получает количество фотографий из данных карточки, а актуальные
CDN-хосты — из карты Wildberries. Превью загружаются в размере `c246x328`, для
скачивания используется размер `big`. Фотографии собираются в ZIP прямо в
браузере.

Наличие видео определяется по `media.has_video` в CDN-файле
`info/ru/card.json`. Приложение передаёт HLS-плейлист `index.m3u8` библиотеке
Mediabunny, которая переносит потоки H.264 и AAC из MPEG-TS в контейнер MP4 без
перекодирования и потери качества.

Такой подход позволяет MVP скачивать медиа без собственного backend-пайплайна
для видео. Remux заметно легче полного перекодирования, поскольку не меняет
исходные аудио- и видеопотоки.

## Что нужно доделать для production

- Перенести обработку видео на backend и отдавать готовый MP4 потоково, не
  удерживая файл целиком в памяти браузера.
- Добавить обработку видео с кодеками, которые нельзя напрямую перенести в MP4.
- Проксировать запросы к Wildberries через backend вместо зависимости от Vite
  proxy и доступности CDN из браузера.
- Ввести таймауты, повторные попытки и лимиты на число файлов, размер загрузки и
  параллельные запросы.
- Кэшировать карту CDN и добавить мониторинг изменений ответов Wildberries.

## Ограничения

- Используются публично доступные, но не документированные для этого сценария
  endpoints Wildberries: их формат и маршрутизация могут измениться.
- Прямые запросы из браузера ограничены CORS и anti-bot-механизмами.
- Mediabunny собирает MP4 в памяти браузера и выполняет только remux совместимых
  потоков; большие файлы и другие кодеки требуют backend-обработки.
- MVP ищет только одно видео в фиксированном качестве `1440p`.
- Отдельного превью видео в используемых данных карточки нет, поэтому интерфейс
  показывает первую фотографию товара.
